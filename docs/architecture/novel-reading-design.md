## 导入与不可变定位

1. 接收 `.txt` / `.md`，严格 UTF-8（允许 BOM），非法字节和空正文拒绝。去 BOM、统一换行 LF；不做 Unicode 归一化或字词替换。
2. TXT 提供 `TXT_CN_CHAPTER_V1`（独立行“第…章/回/节”，有限中文/阿拉伯数字）、`TXT_EN_CHAPTER_V1`（独立行 Chapter + 数字）和 `SINGLE_CHAPTER_V1`；无命中时要求选择单章，不自行猜测。匹配规则受长度约束，不接受用户正则。
3. Markdown 使用用户选择的固定 ATX 标题级别 H1/H2/H3 分章，跳过 fenced code 内的标题；前导正文作为序章。非标题文本保留为纯文本，首版不渲染原始 HTML、图片或链接资源。
4. TXT 的非空行形成段落；Markdown 的空行分段，代码围栏块作为独立文本段。空行仅作展示间距，不计入已读位置；超长段落按完整 Unicode code point 确定性拆成阅读段，预览提示拆分数量。章标题存独立字段，不成为正文段。
5. 保存原文件 SHA-256、规范化正文哈希、解析规则/参数/版本、不可变章节和段落；确认导入绑定预览哈希。相同主体、文件哈希与解析合同重复导入返回既有版本，不产生第二份正文；换规则或正文产生新版。
6. 章节/段落 UUID 与序号只在同一版本内稳定；版本内全局 `paragraphOrdinal` 从 1 连续编号。范围可简化为 `0..B`，`B=0` 表示未读。段内 offset 用 Unicode code point，禁止 Java UTF-16 与 JS 字符串偏移混用。
7. 解析和正文持久化成功即 `READY`；索引另行执行。文件保留在 StorageService 内由服务端生成的 key，普通移除不调用物理删除；数据库提交失败保留可追踪的暂存记录，不能留下书架可见的半本书。

## 模块与范围服务

新增 `book`（导入/版本/章节/段落）、`readingstate`（位置/边界/范围与可见性）、`readingnote`（书签/笔记/提案）、`readingtask`（索引/任务/证据/预算）。复用 Spring AI、pgvector、StorageService、CurrentSubjectProvider、trace 与有界线程池配置方式；任务服务、提案事务使用专用实现，不提取通用运行时。

`ReadingScopeService` 产生服务端快照：

```text
ownerId, bookId, versionId, boundaryOrdinal, scopeRevision, visibilityEpoch, dataAsOf
```

所有读取都验证 owner、书籍/版本关系与逻辑删除。`resumeRevision` 和 `scopeRevision` 分离；显式边界每次修改增加 scopeRevision，任何回退额外增加 visibilityEpoch。版本内容不变，恢复位置永不改变范围。

- AI 快照冻结 B；推进边界也只用原 B。回退使旧 epoch 的活动任务失效，即使随后重新前进也不能恢复那个任务；用户可新建任务。
- 任务发布与边界写入锁同一 reading_state 行，检查当前 epoch、当前 B、executionId 和状态，在同一事务落库，避免“先检查再回退”的竞态。
- 历史结果、缓存、提案、笔记和引用每次输出均检查其 `requiredBoundary <= 当前 B` 且版本相同。范围标签取整个输入依赖的最大位置，不能只取最终引用的最大位置。
- 首版不做跨任务生成结果缓存、不建立持久全书人物表、不注入历史聊天/旧答案/笔记或回答偏好；幂等恢复仅返回同一个任务，并仍执行可见性检查。未来开启缓存需完整范围键与专项测试。
- 索引只含确定性局部正文片段及技术定位，不能把全书摘要、模型补全或后文人物关系写进段落 embedding。索引中即便留有更高已读进度数据，查询也必须先过滤再评分。
- 原文阅读器允许用户主动跳到未来章节，但此操作不扩大 AI 范围；引用预览走专用受限接口，不能复用不受 AI 边界限制的全文接口。未完全读完的章默认不显示真实标题。
- 未完全读完的章标题也不进入检索 metadata 的可见文本、模型 Prompt 或引用标签，只使用章序号；用户填写的书名/来源说明不作为事实证据或额外模型上下文。导入全目录预览不得流入阅读任务。
- 各标签页订阅范围变更事件，回退提交后清除较后正文结果卡和预览，再拉取受限快照；页面聚焦和断线重连先重新校验再展示 AI 内容。浏览器不持久缓存 AI 正文（响应 `no-store`）；已经发送/被看到的文字无法撤回，不承诺抹除用户记忆或用户自行复制的文本。

当前实现补充：

- `ReadingScopeService.current` 在主体生命周期锁 → `reading_state` 行锁下产生范围快照并组装目录、笔记、书签与原文视图，与边界写入/书籍移除采用相同锁顺序。普通阅读器允许主动读未来正文；专用预览 SQL 同时校验 owner/book/version/deleted 和段序上限，不能用全文读取代替。
- `publish` 在同一事务检查原书籍/主体、冻结边界和 epoch，再执行短数据库回写；不持锁调用模型。前进不扩展原输入，回退再前进也不能复活旧 epoch。本轮任务服务在回调内共同检查 executionId、状态与累计预算；工程门禁不是语义防剧透验收。
- 状态 SSE 用已持久化 `scopeRevision/visibilityEpoch` 生成当前安全元数据；重连忽略历史事件正文，返回最新 `snapshot`，变化发送 `scope_changed`。通知采用有界订阅与周期读取，可能合并多个变化，epoch 保留“曾回退”的事实；不是同步撤回已发送响应。运维限额只在路线维护。
- 段落预览只显示所选已读段落，笔记出处按完整 `requiredBoundary` 校验并使用不可变 Unicode 选区。关闭预览不导航、不写续读；显式“从这里继续读”先重新验证出处，再走原自动保存命令。
- 页面用请求代次丢弃范围变化、切版和关闭后的迟到响应；SSE 出错、聚焦或页面恢复时先隐藏再重验。笔记编辑草稿只在内存暂存，同版本、同 epoch 重验后恢复；回退则丢弃。原文预览与抽屉打开期间不以背景滚动覆盖续读位置。

## 证据、索引与强类型调用

回顾从 B 所在章向前取最多三章（不足则取已有章），当前章只取到 B；按原文顺序读取所有覆盖段落，确定性装箱为证据。超出任一证据/输入预算，在模型调用前返回 `COVERAGE_LIMIT`，建议缩小至一/两章；不抽样后声称回顾了整章。

人物查证采用阅读专用 pgvector 数据表/VectorStore 配置实例，沿用当前 1024 维 profile，避免旧知识库检索误命中。每个向量片段只来自一个完整已读段落内部，可将长段拆为小片段；不使用相邻未读段落的重叠文本。metadata 含 owner/book/version、段序、起止偏移、正文哈希、profile、索引 generation。

候选 SQL/VectorStore filter 必须包含主体、书籍、版本、`paragraphOrdinal <= B`、profile 与有效 generation，候选集内取 top-K 后复核关系、哈希与范围。使用绑定参数/Filter builder；不能将模型文本拼进 SQL。若框架无法证明过滤在候选阶段生效，用专用绑定参数 DataPort 执行过滤子查询后精确向量排序；首版不增加混合检索或 Rerank。

索引由用户显式选择“为已读部分建立/补齐 AI 索引”，先显示待处理段落、字数和预算；默认导入不触发 embedding，范围推进也不自动补索引。人物任务需索引连续覆盖到 B，否则提示补齐；回顾直接读原文，不依赖索引。索引批次在生成前复核当前 B；回退时停止尚未发送的批次，迟到数据只能成为不可查询的暂存 generation。原始段落索引不因使用时 B 更大而依赖后文，完整局部片段在更小 B 内仍可用。预计批次数是实际 HTTP 请求数，适配器进一步拆批也计数，不能用一次 Java 调用掩盖多个请求。

静态强类型应用方法如下，不注册为模型可自由调用的通用工具：

| 方法 | 输入由谁控制 | 输出与校验 |
| --- | --- | --- |
| `ReadRecentChapters(scope, chapterCount)` | scope 服务端；章数只允许 1/2/3 | 顺序正文、完整覆盖区间；超限无模型调用 |
| `SearchReadPassages(scope, query)` | query 为用户问题或一次规划产生的查询 | 预算内 top-K、段落来源、dataAsOf；固定范围和数量 |
| `ReadCitation(scope, evidenceId)` | 服务端证据关联 | 精确原文/偏移，当前范围重验；无外部 URL |
| `PlanCharacterQueries(question)` | 用户主动选多线索模式 | JSON 查询数组；长度/数量/重复校验；不得返回工具名、SQL、owner、版本或边界 |

模型只生成查询或结构化结果；不调用位置写入、索引启动、提案确认、文件/网络或任意 MCP。规划无效直接失败，不付费修复；有效查询数不得静默裁掉多余项。默认查证不使用模型分类或规划。

结果为 `facts[{text,evidenceIds}]`，回顾可按事件、人物、未决疑问分组；“未决”也须有已读证据，不推断作者后续安排。证据编号、原文哈希、版本、范围、结构和字数全部验证后才发布一次正文。已知模型作品先验不能作为来源；自动引用校验只验证结构，语义门槛另由评估验证。

## 任务、预算与失败语义

```text
QUEUED -> RUNNING -> COMPLETED | PARTIAL | INSUFFICIENT_EVIDENCE | FAILED
QUEUED/RUNNING -> PAUSED | CANCELLED | INVALIDATED
PAUSED -> QUEUED（显式恢复，同一快照、累计预算，范围仍有效）
PAUSED -> CANCELLED | INVALIDATED
```

`COMPLETED` 表示工程执行与结构校验完成，不等于语义验收。`PARTIAL` 只用于查证有受支持事实但明确保留问题缺口；默认完整窗口回顾不允许按预算偷偷变为部分回顾。无证据为 `INSUFFICIENT_EVIDENCE`，固定文案“在当前已读范围内无法确认”，不暗示后文。

任务失败码至少包含 `COVERAGE_LIMIT`、`INPUT_LIMIT`、`OUTPUT_INVALID`、`BUDGET_EXHAUSTED`、`PROVIDER_UNAVAILABLE`、`TIMEOUT`、`INDEX_NOT_READY`、`INTERRUPTED_CALL`；边界收缩为 `INVALIDATED/SCOPE_CHANGED`。拒绝入队用 HTTP 429，不伪造模型拒答；入队等待超时为 `FAILED/QUEUE_TIMEOUT`。用户总能回到基础阅读。

调用发送前在数据库原子预留调用次数和预算，写 `STARTED`；响应后补 usage。供应商超时/断线/结果未知仍计已使用一次，不退款、不自动重试；应用与 SDK/HTTP 自动重试都须关闭。暂停/取消即时废止执行令牌，尽力取消网络请求，迟到响应不能回写结果，仍记录已发生的费用事实。

暂停只在安全检查点保留完成证据或已验证模型产物；重启把活动任务转 `PAUSED/RESTARTED`。在途调用没有已落库响应时标记 `UNKNOWN` 且消耗次数；恢复若剩余预算不足以完成，返回 `BUDGET_EXHAUSTED`，必须用户主动新建任务，不能重置计数。

执行时间累计（排队和暂停除外）到上限后失败；每次恢复使用剩余时长，单次下游调用不得超过剩余时长。入队/每步/发布均校验 scope、令牌和预算。取消、失败、完成、失效为终态，新请求重试用新 clientRequestId，UI 先显示新增调用可能产生费用。

## 笔记提案与事务

手写笔记的安全范围至少为创建时 B 与锚点段序的较大值；摘录取创建时 B 与选区终点较大值。AI 笔记保留任务整个输入范围，用户编辑不降低范围标签；以后在更高 B 编辑，安全范围取新旧最大值。回退后较后笔记只显示“超出当前已读范围”的占位，不输出标题/摘要/摘录。

保存入口先校验任务已完成或部分完成且结果当前可见，再将用户最终编辑内容、来源引用、范围、哈希写为不可变提案。不得把编辑内容重新送模型“审核”或伪装为验证过的事实。编辑提案通过新建替代提案实现，事务内将旧待确认提案 `REJECTED/SUPERSEDED`。

确认通过独立请求：锁定范围状态和提案 → 校验 hash、有效期、状态和资源关系 → `EXECUTING` → 插入笔记 → `SUCCEEDED`，同一数据库事务。唯一约束保证每提案仅一笔记；同任务首版仅一份 AI 保存笔记，修改走笔记编辑。重复确认返回既有成功，逻辑删除后也不再创建。

可预期业务校验失败记录 `FAILED` 且不写笔记；过期为 `EXPIRED`。数据库异常回滚笔记和执行权，提案保持原待确认态，返回可重试错误；无法确认提交结果时通过 GET/相同确认请求查既有状态，不能先标成功。提案不可通过客户端更改 owner、范围、来源或 actionType。

本轮实现使用 `ReadingNoteProposalService`、V31 和独立预览组件，沿用主体生命周期锁 → reading_state 的事务序列，统一串行化同主体提案、确认、笔记编辑、范围回退及书籍移除。确认不进入模型/通用动作运行时。提案保留创建时 epoch，回退再前进也不能确认旧提案；已成功笔记则按当前范围重新显示。来源引用复制到笔记，任务移除不级联移除已保存内容。页面刷新通过任务的最新提案恢复最终预览，失败响应先查询持久状态，用户需再次显式确认；范围通知/失焦重验会卸载预览并丢弃在途响应。
