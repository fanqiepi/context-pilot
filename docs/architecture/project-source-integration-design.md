# 项目资料接入设计

2026-10-16，状态：用户明确回复“按这个方案开发”，已整体授权实施。根据产品路线中“通过 MCP 接入限定项目资料来源”细化下一项大功能。研究任务工作台已有首版，本能力补齐从外部项目资料到可持续研究的入口；不将升级影响研究标为已验收。

## 用户闭环

用户在“项目资料”页选择服务器预置的公开项目来源、指定版本和文件路径，预览资料及来源；选择目标知识库并发起导入提案，独立确认后创建本地文档快照。处理成功后可选入现有研究任务工作台，完成计划、执行、带引用结论和补充研究。用户能从文档查看仓库、不可变提交、路径、内容哈希和获取时间。

首版固定公开仓库 `spring-projects/spring-ai`，由用户输入明确 tag 或完整 commit SHA 和 1–5 个文件路径；仅接入 UTF-8 TXT/Markdown。这样可复用已有公开项目研究场景，同时增加可追溯的项目说明与迁移资料。目录浏览、代码解析、私有仓库、其他平台、多仓库和自动同步留待后续范围。

## 模块和 MCP 边界

- 新建 `projectsource` 业务模块，包含来源目录、预览快照、导入应用服务及专用 MCP 客户端适配器。
- 本仓库提供受限 MCP 服务端适配器，暴露两个固定只读工具：`resolve_project_ref` 与 `read_project_document`。由应用固定顺序调用，不交给模型选择，不自动注册发现到的其他工具。
- MCP 服务端只允许上述公开仓库；将 tag 解析为完整不可变 commit SHA 后读取指定普通文件。客户端再次核验仓库、commit、路径、内容类型、长度和哈希，拒绝不匹配结果。
- 使用独立启动的本地服务和预置 HTTP MCP 端点；浏览器、模型和文档不能指定连接地址、启动命令或认证参数。服务端不运行 Shell、不克隆仓库、不读取任意本机文件，不提供写工具。
- 客户端通过窄接口隔离协议 SDK，采用 MCP Java SDK 2.0.0 与 Spring AI mcp-spring-webflux 2.0.0；协议固定 2025-11-25，已通过实际 HTTP 握手和工具调用验证。新增依赖仅用于协议客户端／服务端，不引入工作流框架。
- 现有 V6 `ReleaseNotesClient` 及三个工具保持原合同；现有工作台仍只检索已入库的选定文档，不增加在线外部工具。
- 默认关闭；部署仍限 localhost／可信网络、隐式 LOCAL_OWNER。MCP 不构成认证或多用户隔离。

## 预览和来源冻结

预览是用户操作触发的有界只读抓取，成功后保存不可变快照。整批最多 5 个文件；每文件最多 128 KiB UTF-8，整批最多 512 KiB，每次响应在解码前限流限长。每次工具调用最长 15 秒，整批最长 90 秒，1 个工作线程、2 个排队位置；无隐藏重试。预算是初始限制，不是性能数据。

服务端规范化相对路径，拒绝绝对路径、空路径、`.`／`..` 段、反斜杠、控制字符、编码绕过、符号链接、子模块、目录和不支持的后缀。禁用外部响应重定向，不跟随内容中的链接。上游只使用固定 GitHub API 主机，响应中的 URL 仅校验展示，不用作下一跳请求。

任一文件失败则整批预览失败，不生成可导入的部分快照。返回路径级安全错误，不回传令牌、完整上游响应或内部堆栈。限流、无权限、版本不存在、路径不存在、内容超限、非文本、连接失败、超时及协议不兼容有独立错误码。所有外部内容是不可信资料，不能更改允许列表、模型指令或确认要求。

## 确认导入与失败恢复

新增静态强类型动作 `IMPORT_PROJECT_DOCUMENTS`。仅从用户预览页发起提案，不扩展聊天模型动作解析；参数为服务器快照 ID 和目标知识库 ID。有效预览保留 24 小时，提案到期不得晚于预览到期。确认前再次验证归属、目标库有效性、有效期和内容哈希；确认使用预览保存的字节，不重新读取可变 tag。

复用持久化提案、独立确认、原子执行抢占、幂等结果和审计协议。未确认时允许保存预览数据，但不能创建知识库文档、向量或启动 Embedding。确认事务创建整批文档元数据、来源关联和导入结果，提交后逐文档使用现有处理协调器派发。导入成功表示文档已登记；索引处理状态独立展示，不能把登记成功描述为研究资料已就绪。

当前 `DocumentService.upload` 自行生成文档 ID、写文件及提交元数据，不能直接循环调用作为整批原子导入。实施需抽取保持既有上传行为的内部登记入口：预分配稳定文档 ID 和 storage key，先保存并校验快照字节，再在单一事务写入文档、来源和动作结果。事务失败保留可追踪的暂存记录，恢复复用稳定 ID，不生成重复文档；清理不属于普通业务删除。

同一知识库、仓库、commit、路径及内容哈希采用唯一导入身份；并发确认或不同提案重复导入返回已有文档。已逻辑删除的导入身份不自动复活，返回明确冲突；另行设计重新导入前不绕过删除语义。确认事务未提交时的崩溃会回滚整批登记及执行抢占，用户可重放独立确认；提交后的文档由既有处理恢复扫描继续索引。不重新抓取远端，不自动重放模型调用。索引失败复用既有用户确认维护动作。

## 数据合同

| 表 | 关键字段与约束 |
| --- | --- |
| `project_source_preview` | id、owner、client_request_id、request_hash、repository、requested_ref、resolved_commit、status、expires_at、trace_id、时间、deleted；主体与幂等键唯一，异参重放冲突 |
| `project_source_preview_item` | preview_id、规范路径、media_type、byte_count、sha256、snapshot_storage_key；预览与路径唯一 |
| `project_document_origin` | document_id、knowledge_base_id、repository、commit、path、sha256、fetched_at、preview_item_id、action_proposal_id、时间、deleted；文档关联及导入身份唯一 |
| `project_import_request` | 主体、clientRequestId、预览、目标库和动作关联；提案请求幂等 |
| `project_import_staged_file` | 动作、预分配文档 ID、预览条目和稳定存储键；提案提交时持久化，确认失败后的文件仍可追踪 |
| `project_import_result` | 动作与登记文档关联，整批事务内写入，重复确认读取原结果 |

预览正文通过 StorageService 存储在受管理、gitignored 的目录，不写普通日志。业务记录均逻辑删除。提案与执行结果复用既有动作表，具体迁移编号在实施时按当前 Flyway 序列分配。

## API 和页面合同

| 接口 | 语义 |
| --- | --- |
| `GET /api/project-sources` | 返回服务器固定来源、支持的文件格式和预算；不返回令牌或连接地址 |
| `POST /api/project-source-previews` | sourceId、ref、paths、clientRequestId；202 返回预览 ID；同键同参重放返回原预览，异参 409 |
| `GET /api/project-source-previews/{id}` | 状态、来源、文件安全预览及到期时间；后台处理中轮询，终态停止 |
| `POST /api/project-source-previews/{id}/import-proposals` | knowledgeBaseId、clientRequestId；创建持久化导入提案，重复请求不重复创建 |
| 既有动作确认／拒绝接口 | 独立确认 IMPORT_PROJECT_DOCUMENTS，返回关联文档 ID 和登记结果 |
| `GET /api/documents/{id}/origin` | 返回有效文档的来源元数据；无来源返回明确空结果；删除或无权资源不泄露来源 |
| `GET /api/project-imports/{actionId}/documents` | 返回当前主体导入动作关联的文档 ID，处理状态沿既有文档 API 查询 |

客户端不传 owner、工具名、端点或 storage key。`/project-sources` 页面包括版本／路径输入、异步预览、确认卡片、导入文档与处理状态，完成后链接到知识库和研究工作台；来源页只渲染清洗后的 Markdown／纯文本。新建研究继续使用既有文档选择合同，不静默覆盖现有任务的来源快照。

## 必要验证和交付

1. 固定仓库／工具允许列表、路径规范化、上游重定向、超限与编码校验；恶意正文和额外工具不能触发调用或修改范围。
2. MCP 协议握手、工具 schema 及真实客户端／本仓库服务端交互；未知协议、无服务、超时、断开及取消后的迟到响应不能产生成功预览。
3. 真实 PostgreSQL 验证预览幂等、到期、跨库隔离、并发提案／确认、整批事务回滚、崩溃恢复和删除后重放；未确认零文档／向量副作用。
4. 测试 tag 在预览后移动，确认导入仍使用原 commit 和原字节；来源链接与哈希可复核；文件处理失败可沿既有维护流程恢复。
5. 保持上传、知识问答、维护、比对、记忆、升级研究和任务工作台回归；后端 package、前端 typecheck/build、完整差异审阅。
6. 公开资料真实流程：预览 → 提案 → 独立确认 → 索引完成 → 工作台选文档 → 带引用研究；另验服务不可用、重复确认、刷新与恢复。记录协议版本、代码版本、来源 commit、模型配置及 usage，流程观察与独立语义评分分开。
7. 同步启动配置、演示步骤与验证报告；不把协议单测或单次成功流程称为语义验收完成。

## 授权决定

批准本合同意味着：在既有禁止通用 MCP 接入的规则下，允许上述专用只读 MCP 适配器和 `IMPORT_PROJECT_DOCUMENTS` 确认动作，连续实施完整闭环及必要门禁；不需要对实现切片重复授权。本次授权允许新增完成合同所需的生产依赖、迁移和运行接口。若需要首版支持其他仓库或资料类型，应先修改这里的固定来源和相应验证合同。

## 首版实现说明

迁移为 V23–V26。导入提案来源为专用页面，聊天来源三个字段仅对此动作允许全为空；数据库 CHECK 保留所有旧动作的非空要求，执行分派也拒绝旧动作缺失聊天来源。源文档登记由 document 模块的内部入口负责，保持现有上传接口不变。数据库确认事务提交后才派发索引。
