# 研究成果审查（已批准开发合同）

2026-10-19：根据“根据开发文档，进行下一个大功能点的开发”的请求，沿产品路线细化项目资料接入之后的研究成果审查。用户随后明确确认“确认完毕，可以开始任务”，批准本合同整体实施；不改变既有功能的验收状态。实现检查点不再重复授权。

## 用户结果与范围

用户在研究任务工作台完成一轮研究后，主动点击“审查结果”，获得逐项结论的证据支持判断、引用问题、遗漏和后续建议。原始结果保持不变，审查结果独立保存且刷新可恢复。用户可编辑建议，明确点击“补充并重新研究”，复用工作台 SUPPLEMENT 产生新轮次；新结果需要用户主动重新审查。

首版只接入 taskworkspace 的 COMPLETED 结果，使用该轮已经持久化的证据。INSUFFICIENT_EVIDENCE 展示原有资料不足状态，不生成“审查通过”。不审查普通聊天、V4 比对或升级研究，不增加外部检索、自动修订、自动重规划或自动报告保存。独立审查指独立模型请求与上下文，不宣称不同模型、独立事实来源或多 Agent 协作。

交付闭环为：项目资料导入 → 研究任务 → 证据审查 → 用户补充 → 新轮研究 → 再审查。报告保存和外部行动交付仍为后续范围；现有 SAVE_RESEARCH_REPORT 绑定升级研究，不借本次改成通用保存接口。

## 架构与输入输出

新增专用 researchreview 业务模块，固定应用步骤为快照校验、确定性引用检查、一次模型审查、结果结构校验、持久化。复用 Spring AI 模型配置与调用审计方式，不新增生产依赖、Agent 框架或工具循环，不改变三类顶层聊天路由。

从当前主体的工作台任务构建不可变快照：任务 ID、revision、轮次、知识库、目标与用户补充、答案、证据账本、文档版本信息及内容哈希。客户端仅提交任务 ID 和 expectedTaskRevision，不能提交答案、证据、owner 或模型参数。启动前及完成写回前通过领域接口核验来源仍可用、归属与索引版本一致；不能跨知识库或从历史答案补造证据。

确定性校验检查原答案引用格式及引用 ID 是否属于快照；失败仍生成可解释的问题列表，但不调用模型。模型只能返回结构化审查条目，不调用任何工具：

- claim：答案中被检查的原文短句，必须是答案的精确子串；最多 12 条，每条最多 400 字符。
- verdict：SUPPORTED、PARTIAL、UNSUPPORTED 或 CONTRADICTED。
- evidenceIds：最多 4 个当前快照证据 ID；SUPPORTED/PARTIAL/CONTRADICTED 必须有引用，UNSUPPORTED 可为空。
- explanation：最多 600 字符的可展示依据说明，不保存隐藏思维链。
- gaps：最多 5 项、每项 300 字符；说明目标未覆盖或证据不足之处。
- suggestedSupplement：最多 2000 字符，仅作为可编辑建议，不直接触发任务命令。

服务端整体校验结构、长度、枚举、原文定位与证据 ID；非法输出为 FAILED，不容错成通过。通过结构校验不等于事实正确。总体状态由服务端推导：存在确定性引用错误或 CONTRADICTED/UNSUPPORTED 为 ISSUES_FOUND；存在 PARTIAL 或 gaps 为 NEEDS_MORE_EVIDENCE；其余为 NO_ISSUES_FOUND。页面必须表述“本次审查未发现问题”，不称“事实已验证”；条目不是对所有断言的完整覆盖保证。空条目禁止得到 NO_ISSUES_FOUND。

所有答案、证据与审查内容都视为不可信数据。版本化 Prompt 明确这些内容不能改变输出合同、预算或安全规则；不注入回答偏好，不允许审查结果成为新轮次证据。用户手动采纳的补充只能成为任务约束。

## 预算、状态与恢复

每次审查最多 1 次模型请求，无隐藏重试；输入最多 30000 字符，证据最多 16 条／12000 字符，答案最多 4000 字符，结构化结果序列化最多 16000 字符。预算不足明确失败，不静默截断导致漏审。单次执行硬超时 90 秒，独立有界执行器 1 个运行槽、2 个排队槽；排队最长 180 秒。调用使用有界隔离池，槽位释放与迟到结果防护不能产生无界后台调用。初始预算不代表实测性能。

状态 QUEUED → RUNNING → COMPLETED / FAILED；QUEUED 或 RUNNING 可 CANCELLED。执行结果另存 overallVerdict，与执行状态区分。取消、超时、任务补充或删除、来源变化均使执行令牌失效；迟到结果不得覆盖终态。重启时未完成记录收敛为 FAILED/REVIEW_SERVER_RESTARTED，用户主动重试创建新记录，不自动重放付费请求。不得宣称本地取消会停止供应商计费。

每主体每任务快照最多 3 次审查尝试（含取消、失败），并发最多 1 个活动审查。clientRequestId 重放返回同一记录；同键不同参数返回冲突。队列拒绝保留可查询失败记录及错误码。新轮次与旧审查隔离，旧记录显示“历史轮次”；同轮来源变更显示“来源已变化”。

## 数据与 API

新增 Flyway 表 research_review：id、owner_id、task_id、task_revision、round、client_request_id、request_hash、snapshot_hash、snapshot_json、status、overall_verdict、result_json、revision、execution_id、error_code、trace_id、prompt_version、model、usage_json、started_at、completed_at、created_at、updated_at、deleted。唯一约束 (owner_id, client_request_id)，并发与尝试上限由事务锁保障；普通删除采用 deleted=1，删除后不得借原幂等键重新执行。

快照及终态结果不可变；执行状态和 revision 在事务中更新。列表只返回摘要，详情返回原答案、审查条目及对应证据；日志不输出研究目标、全文或证据。主体由 CurrentSubjectProvider 获取；读取审查必须同时核验父任务仍对当前主体可见，父任务删除后不能通过审查接口继续读取其内容。来源文档删除后隐藏对应片段并标记失效，不能继续展示为有效支持证据。

拟定接口：

| 接口 | 合同 |
| --- | --- |
| POST /api/research-tasks/{taskId}/reviews | clientRequestId、expectedTaskRevision；创建不可变审查快照，返回审查详情，异步执行 |
| GET /api/research-tasks/{taskId}/reviews | page/size，size ≤ 50；分页摘要，包含轮次和时效标记 |
| GET /api/research-reviews/{id} | 当前主体详情、执行状态、revision、结果、来源时效与 usage |
| POST /api/research-reviews/{id}/cancel | expectedRevision；原子取消，重复取消无副作用 |
| DELETE /api/research-reviews/{id} | expectedRevision；只允许终态逻辑删除 |

任务过期 revision、状态不允许、尝试耗尽分别返回明确的 409；无权或已删除资源返回 404；参数非法返回 400。模型结构错误、超时、来源变化、队列拒绝和重启通过可查询记录暴露稳定错误码，不能假装审查成功。

前端在现有研究任务页加入审查入口、状态、问题列表、原文/证据对照与历史轮次标记。活动审查有界轮询，卸载或终态停止。补充建议先填入可编辑输入框，只有用户点击现有 SUPPLEMENT 提交按钮才产生新轮次；revision 冲突要求刷新，不自动覆盖用户输入。不新增业务动作，也不削弱已有业务动作的独立确认要求。

## 实施检查点与评估

实施时先同步 AGENTS.md、产品需求、总体架构、数据模型、API、评估计划和项目概览，再连续实现：

1. 冻结公开测试案例与结构合同；迁移、主体隔离、幂等及快照读取。
2. 确定性引用检查、一次模型审查、结果校验、预算、取消与重启恢复。
3. 工作台审查入口、问题证据对照、历史与用户编辑补充闭环。
4. 最小相关测试、真实 PostgreSQL 生命周期、完整相关回归、前端类型检查/构建、公开流程页面核验与验证记录。

固定工程案例至少覆盖：正确支持、证据部分支持、无支持、矛盾、伪造引用、空输出、断言不在原文、超限、恶意证据指令、跨主体/知识库、来源变更/删除、父任务补充/删除、同键重放/冲突、并发启动、尝试上限、排队拒绝/超时、运行超时、取消后迟到、重启、逻辑删除及历史恢复。必要并发/事务门禁使用真实 PostgreSQL；Mock 不代替数据库证据。

真实模型采用公开资料和独立标注样本，记录输入快照、代码/Prompt/模型版本、执行终态、条目、误报/漏报及人工证据支持判定。至少覆盖支持、部分支持、不支持、矛盾四类，每类两次；该规模仅说明代表流程，不声称总体准确率。工程通过、流程通过与语义质量分别登记，失败原始记录保留；未运行的项目明确列出，不算通过。不改写 V6 待验收结论，不以审查器自评分充当验收证据。
