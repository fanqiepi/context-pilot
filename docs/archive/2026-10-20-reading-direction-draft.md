# 研序 产品方向与开发安排

> 更新：2026-10-20。本文件是唯一当前产品路线。用户认可小说阅读方向，并授权本次文档整理及旧计划取舍；新业务尚处于产品设计阶段，未授权实现具体功能。既有实现、验收及技术标识保持原状，新产品名称待定。

## 产品决定

求职目标是展示完整业务中的 AI 应用开发能力。现有研序已形成检索、证据、受控动作和任务执行框架，接下来围绕明确读者场景设计业务，不继续以增加研究工具或 Agent 框架作为目标。

目标用户：阅读长篇小说、会中断阅读、容易遗忘人物和前情的读者。

拟提供的价值：**帮助读者记住故事、理清人物，在中断后快速接着读。**

首个核心场景：用户隔了两周回来，系统根据其上次阅读位置，整理已读剧情、相关人物和仍未解答的问题，支持回到对应原文，并由用户选择是否保存回顾笔记。这是拟设计的产品闭环，不是现有能力。

主流程草案：打开书架 → 继续阅读 → 请求前情回顾 → 服务端确定已读范围 → 检索和整理依据 → 展示回顾及原文跳转 → 用户选择保存笔记 → 回到阅读位置。

## 第一版范围草案

| 层次 | 优先讨论的能力 | 产品作用 |
| --- | --- | --- |
| 阅读业务 | 用户有权使用的书籍导入、书架、章节阅读、进度、书签与笔记 | 不使用 AI 也能完成阅读与续读 |
| AI 阅读 | 已读剧情回顾、人物与事件查证、引用与原文跳转 | 解决忘记前情、人物混淆和查证困难 |
| Agent 任务 | 读取进度、限定资料、按需检索、整理证据、呈现结果与保存提案 | 让模型使用明确业务状态和受控工具完成任务 |

先做完整的“中断后续读”流程，再考虑人物关系可视化、跨章节事件梳理、阅读计划或推荐。简单任务允许固定编排；只有需要动态选择检索步骤的任务才考虑有限规划。工具列表、预算、状态与写入语义需在详细设计中确定，不直接照搬旧研究合同。

第一版不默认纳入版权书城、付费分发、抓站、社区、作者创作平台、角色陪聊、音频、移动端原生应用或多 Agent。平台内容供应和商业化不是本次范围；演示优先使用自创或许可明确的文本。小说不因改为文字就没有版权约束。

## 阅读范围与正确性

- “不泄露未读剧情”是待验证的核心要求，不是已具备或绝对保证的能力。模型已有知识也可能泄露剧情，不能只依赖提示词。
- 在服务端限定书籍、版本及阅读边界；检索、章节摘要、人物资料、缓存、历史任务结果和引用展示均需遵守相同范围，不能仅过滤最后一次向量查询。
- 进度以什么为准（最后位置、最高已读位置、用户确认已读范围）、是否允许跨章跳读、同章未读部分如何处理，必须先定义。进度回退及不同设备的结果可见性也需设计。
- 书籍重新导入、章节修订与目录变动需明确版本和来源定位；知识库文档/分块不能直接视为已完成的书籍/章节模型。
- 无依据的人物关系、因果和悬念不得编造；回顾必须能跳回支持结论的原文。原作事实与任何创作内容分开。
- 阅读进度和笔记属于业务状态，不写进 V5 的回答偏好记忆。Agent 发起写入应保留可审阅、确认、幂等与审计；普通阅读器自动记录进度的 API 语义需单独设计。

## 现有资产如何承接

| 资产 | 处置与限制 |
| --- | --- |
| Spring AI、模型适配、PostgreSQL/pgvector、存储与有界后台任务 | 保留基础设施；新格式解析、章节化和索引元数据另行设计 |
| 检索、证据校验、引用、拒答 | 优先复用服务边界；增加书籍/版本/阅读范围约束及章节定位 |
| SSE、任务状态、检查点、取消与预算 | 复用机制与验证经验；新阅读任务合同另定 |
| 强类型动作、持久提案、独立确认、原子幂等 | 用于未来经确认的笔记保存等动作；现有保存报告不等于已有笔记功能 |
| 显式回答偏好 | 保留呈现约束；不充当角色记忆、剧情档案或阅读进度 |
| 现有知识库、聊天、比对和维护页面 | 保留实现作为工程基线；新产品主入口另行设计，不把所有旧入口塞进阅读流程 |
| 升级影响研究、Spring AI 专用 MCP、成果审查 | 保留代码/合同/证据；不强行接入阅读主流程，不默认泛化为阅读工具 |

当前代码仍是单用户知识工作区，没有小说阅读器、章节进度模型或防剧透实现。已有用户主体不是登录认证。建议先讨论单用户 Web 闭环；是否支持账号、多设备及公开部署由产品范围决定，若需要，必须补齐认证、资源所有权和授权设计后才能开放。

## 接下来要确定的设计

1. 明确首版用户旅程和成功标准：回顾是否帮助读者继续读、事实与引用是否可靠、是否泄露未读信息，以及耗时/费用是否可接受；尚无测量成绩。
2. 决定内容来源与导入格式、阅读进度语义、单用户还是账号体系，以及书架/阅读页/回顾面板的关系。
3. 对照现有代码，设计书籍、版本、章节、进度、笔记和阅读任务边界；写明复用、适配、新增与旧入口保留方式。
4. 冻结详细范围、数据/API、Agent 工具与预算、失败语义、测试语料和验收方法；获得实施范围确认后开发。确认后的合同按完整闭环推进，不重复请求切片授权。

技术架构、数据模型和 API 文档目前仍描述既有实现；本页草案不提前增加未实现字段或接口。历史能力编号和技术标识继续保留，任务以具体用户能力命名。
