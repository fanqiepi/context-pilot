# ContextPilot 功能清单与简历素材

最后核对：2026-10-16。覆盖当前工作区（含尚未提交的 V6 实现），不代表已发布版本。

本文用于持续维护“项目现在能做什么、证据在哪里、可以怎样介绍”。它是功能索引，不新增需求或实施授权；详细路线仍以[产品需求](../requirements/product-requirements.md)为唯一来源，具体合同以版本设计为准。

## 状态口径

| 状态 | 含义 |
| --- | --- |
| 已验收 | 所属版本范围已有验收依据，可作为已完成功能介绍 |
| 已实现／待验收 | 代码已落地，有部分验证；不能宣称版本交付或质量达标 |
| 部分完成 | 仅完成部分资产或步骤，剩余事项需明确记录 |
| 方向候选 | 未授权实施，不属于当前功能 |

当前结论：**V1–V5 为已验收基线；V6 首版已实现，但版本验收未通过，新建研究默认关闭。** 当前是单用户应用，适用于本机或可信网络；隐式 `LOCAL_OWNER` 不是登录认证或多用户隔离。

## 可用于简历的素材

项目名称建议：**ContextPilot：基于 Spring AI 的可追溯知识研究与受控行动助手**。

技术栈：Java 21、Spring Boot 4.1、Spring AI 2.0、PostgreSQL／pgvector、MyBatis-Plus、Flyway、Vue 3、TypeScript、SSE；DeepSeek 负责生成，DashScope 负责 Embedding。

以下条目按岗位选择 3–5 条，并确保能解释代码、设计取舍与验证证据：

| 主题 | 可改写进简历的表述 | 面试准备依据 |
| --- | --- | --- |
| RAG 全链路 | 实现文档解析、切分、向量化、知识库隔离检索与流式问答，结合证据校验、引用和拒答机制提供可追溯回答。 | V1-02–05、V1-07 |
| 业务动作可靠性 | 设计持久化提案与确认状态机，通过强类型参数、静态分派和原子幂等确认，支持创建知识库、文档重试及索引重建。 | V2-01–03、V3-02–03 |
| 多文档研究 | 实现 2–5 份文档的确定性多步骤检索与综合，使用有界并行、执行预算和来源引用控制研究过程。 | V4-01–03 |
| 显式记忆 | 实现经用户确认的回答偏好记忆及版本化管理，提供有界注入、单次忽略与历史追溯，限制偏好只影响回答呈现。 | V5-01–04 |
| 评估与可观测性 | 建立版本化评估资产、真实 PostgreSQL 集成验证和模型调用审计，分别记录工程回归、真实模型效果与未通过验收项。 | 版本验收报告、[评估入口](../../evals/README.md) |

V6 若需写入，应单列为进行中：**“实现基于 Spring AI 原生工具调用的受控升级研究原型，限定三个只读工具、执行预算与来源范围，并通过独立确认保存报告；已完成真实联调，正在进行专项质量验收。”** 不写成已经稳定交付的自主研究 Agent。

可引用的量化证据必须带范围：V5 有 16 次真实模型回答对照；425 项是 2026-10-15 工程测试快照。不得把小样本风格符合度写成通用问答准确率，不得补造延迟、并发、费用或效率提升百分比。

尚不属于当前交付：MCP、多 Agent、LangGraph／工作流引擎、混合检索／Rerank、自动记忆提取、通用自主工具、OCR、登录认证、多租户。V7 及更远期方向只查阅产品需求，不列入“已完成”。

## 更新规则

1. 每次功能发生变化，在同一变更中更新对应编号行、核对日期和证据链接；新功能追加编号，撤销功能保留记录并说明原因。
2. “有代码”“工程检查通过”“真实模型联调通过”“版本验收通过”分别记录，不能互相替代；仅在验收报告明确通过后把状态改为“已验收”。
3. 默认开关、输入范围、确认要求或失败语义有变化时，同时更新对应设计、接口和需求文档，再同步本索引。
4. 测试数值保留执行日期与范围；新结果替换此处快照时链接新报告，不覆盖历史证据。
5. 简历措辞跟随功能状态调整；新大版本的授权与路线仍在 AGENTS.md 和产品需求中维护。
