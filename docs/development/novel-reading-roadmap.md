## 产品目标与首版范围

面向会中断长篇小说阅读、容易遗忘前情与人物的读者，提供完整的“回来接着读”体验，同时展示业务建模、受控检索、证据引用、有界任务、人机确认和可评估性等 AI/Agent 应用开发能力。

首版采用单用户 Web、用户主动导入 UTF-8 TXT/Markdown、段落级连续已读范围。完成书架、目录、阅读器、续读位置、书签、笔记、已读剧情回顾、人物查证和原文跳转。不依赖 AI 也能完成基础阅读。

首版不包含 EPUB/PDF 小说阅读、OCR、抓站、版权书城、付费分发、社区、作者创作、角色陪聊、音频、原生移动端、离线阅读、账号体系或多设备同步。EPUB、人物关系图、全量已读剧情梳理与分层摘要是后续候选，不自动进入排期。旧知识库已有 PDF 能力继续保留。

混合检索、Rerank、通用 MCP、多 Agent、工作流引擎不作为求职展示的默认扩展。出现可测量的阅读任务问题时，再单独评估是否需要。

## 用户旅程与页面

主流程：导入小说 → 核对目录 → 开始阅读 → 保存续读位置 → 中断后返回 → 确认已读边界 → 查看回顾 → 查证人物或跳转原文 → 可选保存笔记 → 回到阅读位置。

| 页面或区域 | 首版行为 |
| --- | --- |
| 书架 | 最近阅读优先；显示书名、阅读位置、上次阅读时间、导入状态；提供继续阅读、回顾后继续、导入和移除入口 |
| 导入向导 | 选择文件、填写书名与来源说明、预览分章、确认导入；失败显示可操作原因 |
| 书籍详情 | 目录、版本、阅读状态、书签和笔记入口；未读章节标题默认隐藏，只显示序号 |
| 阅读页 | 正文、目录、字体/行距/主题设置、书签、选文笔记、自动保存续读位置；长篇正文按章加载 |
| 阅读助手面板 | 前情回顾、人物查证、任务状态与重试入口；始终显示已读范围和结果覆盖范围 |
| 本书笔记 | 区分手写、原文摘录和已确认的 AI 回顾；支持编辑、逻辑删除及跳转出处 |

桌面采用可收起的目录、正文、助手布局；窄屏使用抽屉。研究任务操作不成为普通阅读的前置步骤。新阅读页面使用独立路由，不能把当前 `/library` 知识库页面直接解释成书架；旧入口在实施时收纳到原有工作区，保留直接访问。

用户两周后返回第 38 章中段时，默认回顾最近三个已读章节，当前章只包含已确认读过的完整段落。展示最近事件、涉及人物、截至该处尚未明确的疑问；缺乏依据的栏目可以为空。点击人物可继续查证；引用打开临时原文预览，关闭后返回原续读位置。用户可以直接继续阅读，也可以主动保存回顾笔记。

## 内容导入与版本

- 只接收用户有权使用的文本；演示随附自创或许可明确的小说，记录来源及许可说明。已有 Spring AI 项目资料 MCP 不能用于小说采集。
- TXT 使用明确规则识别章节；Markdown 使用约定的同级标题。导入前展示章节数量、首尾正文和划分结果，允许更换规则或作为单章导入，不调用模型猜目录。
- 保存原文件、哈希、解析规则版本和规范化正文；段落定位以该不可变版本的正文为准。首版保留基础文本格式，不执行原始 HTML，不自动加载外部资源。
- 正文解析可用与 AI 索引可用分别记录。索引失败不阻断阅读，可独立重试；普通移除采用逻辑删除，不物理清理业务记录或上传文件。
- 相同文件重复导入提示已有版本；正文或解析规则变化生成新版本。旧进度、引用和笔记继续绑定旧版，不自动迁移位置。
- 文件大小、章节数、单章长度、书架规模及正文分页上限按下文冻结容量执行；限制已批准，实测范围另见验证记录。

### 已冻结容量

全部“字符”按 Unicode code point 计，上传按字节计；字符数、token 和费用不同。任一上限到达即拒绝或要求用户缩小，不默默截断。

| 项目 | 首版硬限制 |
| --- | --- |
| 文件与正文 | 单文件 20 MiB；规范正文最多 500 万字符；只允许 UTF-8 TXT/Markdown |
| 书架与版本 | 单主体最多 100 本未删除书；每书最多 5 个保留版本（含已逻辑删除）；暂存和已保留原文件累计最多 1 GiB，逻辑删除不释放物理额度 |
| 解析结构 | 每版最多 5000 章、200000 段；单章最多 200000 字符；单阅读段最多 4000 字符，超长原段确定性拆分并在预览提示 |
| 目录与正文分页 | 目录默认 50/最多 100 项；正文默认/最多 100 段且不超过 20000 字符，完整段返回，游标接续 |
| 预览 | 有效期 24 小时；最多 3 个未过期活动预览；首尾样本各最多 500 字，目录分页；过期不自动物理清理文件 |
| 元数据/笔记 | 书名/笔记标题/书签标签最多 120 字；来源说明最多 1000 字；笔记正文最多 5000 字 |
| 提案 | 有效期 30 分钟；每任务最多 1 个待确认提案、1 份 AI 保存笔记；替代提案原子拒绝旧提案 |
| 基础处理 | 解析 1 执行槽 + 2 排队槽；等待 60 秒、执行 120 秒截止；单次结构化数据库查询超时 3 秒 |

正文就绪后可阅读，索引仍独立。原文件额度达到上限时明确拒绝继续上传，物理回收属于单独维护流程，不借普通移除偷偷删除文件。

## 阅读状态合同

| 状态 | 语义 | 更新方式 |
| --- | --- | --- |
| 续读位置 | 下次从哪里继续 | 阅读器自动保存章节、段落和段内位置 |
| 已读边界 | 允许 AI 使用到哪里 | 用户选择已读到这里、读完本章，或请求回顾时显式确认 |
| 临时查看位置 | 引用预览、目录导航或跳读所查看的位置 | 不自动推进已读边界；引用预览不覆盖续读位置 |
| 书签 | 主动保留的位置 | 独立增删，不改变续读位置和已读边界 |

首版已读范围是从正文开头到某个完整段落的连续前缀，不维护任意已读区间。段内偏移只用于恢复阅读，不将尚未读完的整段交给 AI。

跳到后章不等于此前全部读过。用户设置更远边界时，明确提示此前内容将被视为已读；首次导入已读过的小说也可手动设置边界。回翻旧章不自动降低边界，只有重设已读范围才回退。引用预览中的“从这里继续读”才替换续读位置。

多标签页通过状态修订号处理写入冲突，不以最大位置合并；自动位置更新和显式边界修改使用不同命令。位置采用版本内稳定的章节/段落 ID 与段内偏移，不使用受字体和窗口影响的屏幕页码。

## 阅读范围与防剧透

每个阅读任务由服务端固定范围快照：当前主体、书籍、内容版本、已读边界、范围修订号。客户端和模型不能自行指定 owner 或绕过范围校验。

| 环节 | 强制边界 |
| --- | --- |
| 检索 | 候选阶段即限定书籍、版本和已读范围，再复核返回结果；不能先全书检索再删除越界片段 |
| 分块与原文读取 | 保存段落范围，AI 输入不得跨越已读边界；同章后半段不因章节已打开而可见 |
| 摘要 | 摘要输入覆盖范围必须完全在已读范围内；不允许裁剪全书摘要冒充前情 |
| 人物资料 | 身份、别名、关系只来自已读证据；不预载全书人物表中的隐藏身份 |
| 缓存 | 键包含主体、书籍版本、范围、任务输入与 Prompt 版本；高进度结果不能命中低进度请求 |
| 历史与笔记 | 超出当前边界的旧结果保留但隐藏标题、正文及摘录；不能进入新任务上下文 |
| 引用 | 服务端生成定位，验证版本、原文一致性与范围；预览不夹带未读上下文 |
| 目录与界面 | 默认隐藏未读章标题，避免在摘要之外泄露信息 |
| 运行中任务 | 进度推进不扩大任务快照；边界收缩阻止旧任务发布，取消或恢复后都重新验证范围 |

从第 38 章重设到第 20 章时，已有第 38 章回顾不删除，但当前上下文不能展示其内容、复用缓存或传入模型。笔记作为用户材料也不自动成为小说事实证据；手写笔记、正文和模型输出均按不可信数据处理。

引用编号合法不能证明结论正确。阅读结果应按事实条目绑定证据，禁止无依据的人物关系、因果和后续预测。模型本身可能记得作品，必须用已知作品及自创故事测试先验知识泄露；“不剧透”是验收目标，不是绝对保证。

首版通过 SSE 展示状态；正文完成结构、范围和引用检查后再整体发布，避免未检查的 token 先到达界面。证据不足统一说明“在当前已读范围内无法确认”，不暗示后文是否存在答案。自动检查仍不能代替语义验收。

## 身份与部署范围

沿用 `CurrentSubjectProvider` 和 `LOCAL_OWNER`，用于本机或可信网络内的单用户 Web。新书籍、进度、笔记、任务、提案均记录服务端所有者；章节、证据和引用必须通过所属书籍校验资源关系。主体归属不是登录认证。

首版不实现注册、密码、JWT/OIDC、多租户或公开在线体验。若需要公开求职演示服务，先单独确认认证、全资源授权、数据隔离与费用控制范围；不能把当前本地应用直接作为公开多用户产品。

以下领域已细化为[数据草案](../data/novel-reading-data-model.md)与[API 草案](../api/novel-reading-api.md)，仍不是现有表、迁移或接口声明。

| --- | --- |

| 阅读状态 | 续读位置、已读边界、状态修订号、更新时间与并发冲突 |
| 书签、笔记 | 手写/摘录/AI 类型、来源定位、范围标记、编辑版本、逻辑删除 |
| 阅读任务、证据与事件 | 范围快照、执行令牌、状态、检查点、累计预算、引用、结果及 trace |
| 阅读笔记保存提案 | 不可变待确认内容、哈希、所属任务、范围、过期时间、请求幂等键与最终笔记关系 |

接口分为导入预览与确认、书架与正文、自动续读位置、显式已读边界、阅读任务、笔记及保存提案六组。领域查询走服务或专用 DataPort，使用绑定参数、字段白名单、数量限制和超时，返回来源及必要的 `dataAsOf`；模型不能生成 SQL。

保存 AI 笔记：用户点击保存 → 编辑内容 → 服务端持久化提案并展示最终预览 → 独立确认请求 → 原子写入笔记。编辑已持久化提案要生成新提案并使旧提案不可误确认；确认时重新校验来源版本、范围、内容哈希及有效期。

保持 `PENDING_CONFIRMATION → EXECUTING → SUCCEEDED/FAILED` 及 `REJECTED/EXPIRED`，并发或重复确认只能产生一份笔记。失败不得留下成功状态与部分写入不一致的结果。普通手写笔记是用户直接 CRUD，进度自动保存是阅读器命令，两者不套用模型动作确认。

## 阅读任务与已冻结预算

前情回顾按原文顺序组织最近三个已读章节的证据，不用一次全书 top-K 查询冒充剧情梳理。人物查证在整个已读范围内搜索。默认固定编排；用户主动选择“多线索查证”时允许一次受服务端校验的查询规划，不增加隐藏分类调用。

| 任务 | 首版上限 |
| --- | --- |
| 前情回顾 | 一次生成，无 embedding；累计执行 90 秒；结果事实文本合计最多 1200 字；供应商输出上限 4096 token |
| 人物直接查证 | 一次检索/一次查询 embedding、一次回答；累计执行 60 秒；结果最多 600 字；供应商输出上限 2048 token |
| 人物多线索查证 | 一次规划（最多 512 输出 token）、最多三次检索/查询 embedding、一次回答（最多 2048 输出 token）；总生成最多两次，累计执行 60 秒；结果最多 600 字 |
| 笔记保存 | 无模型调用；仅业务校验和事务 |
| 每次检索 | top-K 固定 8；单证据最多 1000 字符，3 次最多 24 个去重片段；不为补足去重数增加检索 |
| 每个任务证据 | 最多 24 个片段、合计 24000 字符；回顾完整按序装箱，单段过长可在范围内拆证据但不能丢原文 |
| 用户问题与规划查询 | 问题最多 1000 字符；规划最多 3 条查询、每条最多 256 字符（1024 UTF-8 bytes）；直接检索问题使用同一 1000 字符/4000 bytes 上限 |
| 完整模型输入 | 每次综合含系统提示、定位元数据、证据、问题及 JSON 包装，最多 32768 字符且 65536 UTF-8 bytes；规划输入最多 4096 字符且 8192 bytes；多线索任务累计最多 36864 字符且 73728 bytes |
| 输出与重试 | 每次模型原始响应最多 32768 UTF-8 bytes；超限/截断/无效结构整次失败，不截出半句发布；应用、SDK 和 HTTP 自动重试均为 0 |
| 并发 | 阅读 AI 共用 1 执行槽 + 2 排队槽；索引独立 1 执行槽 + 1 排队槽；同主体/版本最多 1 个活动索引作业；入队等待最多 30 秒 |
| 超时细项 | 单次向量查询含 query embedding 最多 15 秒；规划最多 15 秒；索引每批最多 30 秒、单作业累计 300 秒；生成不超过该任务剩余截止时间 |
| 索引批次 | 仅已读前缀，段内无重叠片段各最多 1000 字符/4000 bytes；每批最多 16 片段且 16000 字符/64000 bytes；单作业最多 500 片段、100000 字符、32 批 embedding HTTP 请求 |

索引 estimate 返回下一段可完整完成的连续前缀；达到作业上限不开始下一段，不宣称已经索引全部 B。范围内剩余段落由用户再次发起补齐，已完成片段不重复付费；超时/结果未知的片段不能自动重发。导入和确认边界默认不触发真实 embedding，人物查证需当前 B 的全部段落索引就绪。回顾无需等待索引。

这些数字是可审核的工程上限，不是性能或质量成绩。输入字符/字节是本地硬限制，token 计数使用匹配模型的计数器（可用时）或保守字节估算并标记 estimated；供应商返回的实际 usage 单独记账，不把估算当账单。输出 token 限制只设置阅读专用调用，不更改 V4 无请求级 max_tokens 合同；若当前供应商适配不能验证有效输出限制，真实阅读调用保持关闭。

### 费用与真实调用授权

- 默认真实阅读生成/embedding 开关关闭，授权额度为 **0 元**；合同确认只授权实施和离线验证，不消耗现有账户额度。
- 拟议的首次完整新场景模型验收批次上限 **人民币 20 元**：含 12 条 DEBUG 一次、48 条 TEST 各两次及这批语料必要 embedding；最终以独立授权的批次清单为准，不本轮执行。20 元为愿意停止的预算，不是完成批次的报价。
- 每次真实任务/索引开始前展示调用数量与预计费用；上限预留需使用经过核实的供应商计价版本、输入 token 上界和输出限制，embedding 同样计入。不能可靠估算上界时拒绝真实调用，不伪造精确金额。
- 预算按授权批次原子预留，失败/UNKNOWN 调用保留预留；usage/账单明确后才结算差额。余额不足、授权到期或价格未知时停止新调用；无 usage 时标记未知，不能按零费用继续。
- 不开跨供应商试验、不后台自动重试、不自动预生成全书摘要；初次语料索引保留并复用，两次 TEST 不能通过复用答案回避生成稳定性测试。若预算不足以跑完则记未完成，另行决定是否追加。

范围超预算时明确缩小回顾窗口或返回覆盖不足，不静默截断后声称完整。首版不承诺全部已读数百章的一次性总结，不默认预生成全书摘要。

服务端固定执行读取状态、确定范围与核验出处。模型仅能提出白名单查询；不能扩大进度、访问网络、调用任意 MCP 或直接保存笔记。任务支持状态查看、取消、暂停和显式恢复；重启恢复为可解释的暂停状态，过期执行令牌不能回写，恢复不能重置累计预算。

无证据返回证据不足；范围变化阻止发布；队列满、超时、索引失败各有明确状态。用户可继续阅读，付费重试须由用户主动发起并计入可见预算。技术失败不能标为语义拒答，部分覆盖不能标为完整成功。

| --- | --- | --- | --- |
| 冻结阅读业务合同 | 本路线 | `reading-contract-v1-draft1` 页面流程、范围、数据/API、强类型工具、预算、失败语义和评估方案 | 2026-10-20 用户以“确认可行”批准；不包含付费执行授权 |
| 导入并持续阅读 | 合同冻结 | TXT/Markdown 导入、目录预览、版本化正文、书架、阅读设置、自动续读、书签和手写/摘录笔记 | 已实现并形成[工程验证记录](../evaluation/reading-library-verification.md)；本轮停在此处，提醒用户提交 PR，不宣称阅读 AI 验收通过 |

| 确认保存回顾笔记 | 阅读任务和笔记 | 提案预览、独立确认、编辑后重新提案、过期/拒绝、笔记管理 | 并发幂等和事务回滚验证通过，引用和范围信息保存完整 |

每一步完成后更新功能清单与对应证据，不以任务终态代替语义成绩。按实际改动运行最小相关后端测试、迁移检查及前端 typecheck/build；改共享能力时补旧合同回归。文档编辑不触发无关构建或付费实验。

## 评估合同

准备一部自创故事，标注每个进度点已知/未知的身份、关系、事件；另准备许可明确的长篇文本验证规模、定位和阅读体验。冻结版本、Prompt、问题、期望证据和评分标准，区分调试集与最终测试集。

必须覆盖：同章后半段揭密、同名人物、别名身份、不同版本结局、询问后续、正文提示注入、模型先验知识、缓存/历史泄露、进度回退、跳读、多标签页冲突、索引失败、取消后的迟到结果与重复确认。

| 维度 | 已批准验收条件 |
| --- | --- |
| 工程安全与一致性 | 固定测试中跨范围泄露、错版定位、重复写入为零；授权、取消、恢复、事务和缓存范围测试通过 |
| 语义防剧透 | 固定语义集出现未读剧情泄露即阻断发布；有限测试通过不代表绝对保证 |
| 事实支持 | TEST 每次运行、回顾/人物各组的事实支持率 pooled 与每题宏平均均 ≥95%；空答不记满分 |
| 引用支持 | TEST 每次运行、两个任务分组的引用支持率 pooled 与宏平均均 ≥95%；无引用的事实也计失败关联 |
| 拒答与覆盖 | 预期无证据题正确拒答 100%；可回答题可用率 ≥90%；回顾关键事实召回每次运行总体 ≥85%、每题 ≥70%；记录误拒答和遗漏 |
| 续读体验 | 直接续读从已加载书架起 1 次操作；引用预览关闭 1 次操作回原位；每条核心流程桌面/窄屏均能完成，零错位与丢已确认保存；至少 5 名试用者中 4 名认为回顾有助接读，未收集则体验验收未完成 |
| 本地性能 | 500 万字/1000 章合成夹具：解析预览与确认各≤120 秒；正文分页/位置写入 30 次采样 p95≤500ms（不含网络），书架首次可操作≤2 秒、继续阅读≤2 秒；记录冷/热与机器配置 |
| AI 性能 | 回顾 p95≤60 秒、直接/多线索查证各 p95≤45 秒（入队起）；硬截止仍为 90/60 秒；TEST 技术失败率≤5%，超时计失败；单用户顺序采样，并发另测队列门禁 |
| 费用 | 遵守获授权批次上限；报告调用数、实际/未知 token、预留/结算成本、索引初建/增量；首版无生成结果缓存，不能报告虚构命中率 |

语义样本拟定 DEBUG 12 问×1、最终 TEST 48 问×2；TEST 为回顾 16、有依据人物 16、无依据/越界 8、对抗/版本 8，详细标注和计算见[评估方案](../evaluation/novel-reading-evaluation.md)。模型最大调用规划：DEBUG 最多 16 次生成/16 次查询 embedding；TEST 每轮最多 72 次生成/80 次查询 embedding（保守按后两组均多线索），两轮合计最多 144/160 次；索引批次另计入同一金额上限。所有任务和预算失败纳入报告，不删除失败来缩小分母。

语义指标按冻结条目人工核对，工程验证、真实模型观察、语义验收分别记录。付费实验必须另获明确授权，不自动重跑旧研究评估。基础阅读可先按工程门禁独立交付；真实语义与体验证据不足时，阅读 AI 保持未验收标识，不宣称整套产品通过。
