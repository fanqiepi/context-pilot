# 研序｜技术研究 Agent：技术复盘

更新：2026-10-20。本文复盘既有研究框架，不是发布或最终验收声明。后续转向小说阅读应用，当前范围见[产品需求](../requirements/product-requirements.md)；这里的研究经历不能描述为已完成阅读业务。

## 解决的问题

个人技术研究需要把资料、问题、引用和后续行动连起来。研序以单用户知识工作区承载这条主线：上传资料后做有依据的问答与多文档比对；复杂目标进入可暂停、可补充的研究任务；固定公开项目资料经预览和确认导入；研究结果可独立审查。创建知识库、维护文档、保存偏好和研究报告都要求先展示提案，再由用户另行确认。

## 关键取舍

| 取舍 | 为什么这样做 | 代价与边界 |
| --- | --- | --- |
| 模块化单体、PostgreSQL/pgvector | 让状态、业务写入与审计保持明确事务边界，减少个人项目的运维复杂度 | 不宣称多租户或分布式高可用；LOCAL_OWNER 只是归属主体 |
| 固定路由＋按能力编排 | 简单交互确定性响应，多文档比对使用逐文档固定检索；只有批准的研究任务才用有限规划或工具调用 | 灵活性受限，但行为、预算与回归范围更容易解释 |
| 强类型提案＋独立确认 | 模型只能提出动作，业务服务负责校验和原子幂等执行 | 用户多一次确认，换取可见、可取消、可追溯的副作用 |
| 有界执行＋持久检查点 | 通过预算、执行令牌、终态条件更新控制取消、超时和迟到写入 | 本地取消不保证供应商停止计算或计费；恢复不等于自动重跑一切 |
| 明确区分工程与语义证据 | 数据库测试证明状态和隔离，真实模型运行暴露结果质量，人工复核判断事实与引用支持 | 测试通过、终态成功和任务真正完成不能混作一个指标 |

## 本轮收尾暴露的问题

核心 50 项首次实跑发现：正文已经拒答，接口仍可能报完成；比对正文有资料缺口，运行却报成功。修复把回答语义与消息生命周期分开，并让状态经过 API、SSE 和历史保存一致传递。普通问答使用同一次生成内的受限状态协议，非法协议失败，不追加模型分类调用。独立 Solstice 调试验证了两条生产路径，但尚不能代替最终独立验收。

升级研究还暴露另一个层次的问题：读取到证据不等于遵守问题范围。模型会把兼容机制问题扩展为完整上线审计，并引入无依据推断。后续澄清问题语义、对照多版候选并采用 upgrade-research-v6，同时将 HTTP 读取超时显式对齐既有预算。新独立采集仍有格式失败和范围偏差，因此功能继续默认关闭；保留失败证据，没有通过过滤缺口来制造成功状态。

## 可复核的成果与尚未完成的工作

V1–V5 已验收；研究工作台、项目资料接入与成果审查已有首版工程及公开流程证据。升级研究首版已实现但质量验收未通过，默认关闭。核心首次实跑、新独立采集、8×2 代表运行和同机干净工作区复跑已完成，不等于全新机器验证。人工事实／引用核查、修复后的最终独立验收与录屏未完成，旧专项收尾现已暂停。

这些资产为阅读产品提供候选复用基础：证据与引用、有界任务、受控写入和评估方法。章节、进度、版本、笔记及防剧透边界需要独立设计；不把原知识库页面换名就算完成转型。
