# ContextPilot 评估计划

> 状态：V1 功能型基线、V2 可控行动助手与 V3 知识库维护助手均已完成。V4 Slice 1 已完成评估集和固定离线基线；结果证明范围化多步检索的必要性，但未证明模型 Planner 优于固定编排，Slice 2 与生产实现尚未授权。

## 目标

计划使用固定、可公开提交的问题集验证检索、引用和回答质量，避免只凭单次演示判断效果。该基线目前延期，在对外发布前补齐；不接入外部评估平台。

## 评估资产

- `evals/fixtures/documents/`：可公开的固定测试文档。
- `evals/datasets/`：问题、参考答案、期望引用和标签。
- `evals/configs/`：模型、切分、topK、阈值和提示词版本。
- `evals/reports/`：可选的脱敏基线报告。

## 最小用例类型

- 文档中存在直接答案的问题。
- 需要组合多个分段的问题。
- 文档没有答案、应明确拒答的问题。
- 身份介绍、问候、能力说明、感谢和告别应命中固定回复，附加知识问题或指令后不应绕过检索与拒答。
- 未选择知识库或缺少必要上下文、应返回澄清提示的问题。
- 容易命中相似但错误分段的问题。
- 带页码 PDF 的引用定位问题。
- 模型或 embedding 调用失败时的错误处理。
- SSE 中断后消息、模型调用状态和 trace ID 是否可关联。

## 指标

- 检索命中率：期望分段是否进入 topK。
- 引用正确率：引用是否支持对应回答。
- 回答忠实度：回答是否受检索内容支持。
- 拒答正确性：无依据时是否避免编造。
- 延迟和 Token：记录端到端耗时、首字时间和 Token 用量。
- 稳定性：固定配置多次运行的失败率和结果波动。
- 正向反馈：统计“有用”标记数量及其占已完成回答的比例，并可按知识库、trace ID 和时间段关联分析；未标记不直接视为负面或错误样本。

任何提示词、切分策略、检索参数、默认模型或引用格式变化，都应更新配置并重新生成基线。真实用户文档、密钥和未脱敏请求不得进入评估资产。

## V2 能力与操作评估

V2 已使用 `v2-routing-action-safety-v1` 数据集、配置和 Maven `v2-evaluation` Profile 验证路由误触发、强类型参数、未确认无副作用、重复/并发确认幂等、失败脱敏和历史恢复。真实状态机案例依赖 Testcontainers PostgreSQL/pgvector，缺少 Docker 时不得以跳过结果生成基线。资产位于 `evals/datasets/`、`evals/configs/` 和 `evals/reports/`，完整结果见 [V2 版本验收报告](v2-acceptance-report.md)。

## V3 健康检查与维护评估（已完成）

V3 已使用 `v3-health-maintenance-v1` 数据集、配置和 Maven `v3-evaluation` Profile 覆盖健康分类、完整性降级、知识库隔离、不可变历史、可信明细、重试/重建资格、动作幂等和可靠派发。2026-08-15 专项运行 118 项测试全部通过，真实接口和页面目检同时通过。固定评估必须使用真实 PostgreSQL/pgvector；缺少 Docker 或生命周期案例被跳过时不得生成通过报告。完整范围见 [V3 详细设计](../architecture/v3-knowledge-base-maintenance-design.md)，结果见 [V3 版本验收报告](v3-acceptance-report.md)。

## V4 知识研究评估（Slice 1 已完成）

V4 评估范围见 [V4 知识研究助手详细设计](../architecture/v4-knowledge-research-design.md)。在实现运行时、数据库迁移或前端入口前，必须先建立同一文档集、同一问题集和可比较预算下的两组基线：

- 当前单轮 RAG：一次检索、一次证据校验、一次回答生成；
- 候选受限 Plan-and-Execute：强类型计划、有限只读检索步骤、证据账本和一次最终综合。

Slice 1 范围允许在 `evals/`、测试源码和评估文档内提交公开或合成语料、问题与期望证据、配置、评分规则、执行脚本、评估专用候选编排原型和脱敏报告。候选原型不得被生产代码调用，不得引入 Flyway、正式 API/SSE 或前端入口；评估完成后依据结果另行决定是否授权 Slice 2。

Slice 1 已建立完整的 32 个语义案例和 12 个生命周期案例定义，并只对评估原型当前真实具备的能力生成基线。持久化、取消、SSE、重启恢复和页面案例仍须在对应生产切片实现后转为可执行验收；Slice 1 报告只提供后续范式与切片评审证据，不代表 V4 已通过完整验收。

第一阶段数据集只评估由显式 `research.taskType = DOCUMENT_COMPARISON` 进入、选择 2 至 5 份文档的多文档比对。固定语义集共 32 例：8 个单轮 RAG 已足够的对照案例、12 个确需多步覆盖的比较案例、4 个局部缺失案例、4 个全局无依据案例和 4 个提示注入/范围隔离案例；另建立至少 12 个真实生命周期案例，并对代表性 8 个模型案例各重复运行 3 次。

案例至少覆盖：

- 单次 Top-K 能完整回答的对照题，防止不必要规划增加成本；
- 普通聊天中的“比较”等措辞不得自动触发研究运行；
- 必须分别命中不同文档或不同子主题才能完整回答的多步题；
- 某份文档缺少一个比较维度，结果应明确局部缺失；
- 全部材料无依据，应保持拒答；
- 相似文档、重名文档和越界文档，验证范围隔离与引用来源；
- 文档中的提示注入文本不能改变计划预算或允许步骤；
- Planner 输出非法 schema、重复步骤、越界文档或超预算计划；
- 单步检索失败、Planner/Synthesizer 失败、90 秒超时、用户取消、SSE 断开、幂等重复、历史恢复和应用重启；
- V1-V3 普通 RAG、健康报告、动作确认和历史恢复回归。

通过阈值固定为：

- 显式入口、选中文档覆盖、范围隔离、预算和生命周期幂等案例 100% 通过；越界命中和预算超限均为 0；
- Planner 首次或一次修复后的 schema 有效率不低于 95%；
- 多步子集任务完成率与维度覆盖率不低于 85%，且任务完成率相对单轮 RAG 至少提升 15 个百分点；
- 引用正确率不低于 95%，引用覆盖率与回答忠实度不低于 90%；
- 局部缺失、拒答和无效引用处理正确率不低于 90%；
- 对照子集相对单轮 RAG 的质量下降不超过 5 个百分点；
- 所有运行在 90 秒内进入终态，模型调用不超过 3 次、检索不超过 20 次、证据不超过 24 个 chunk，并满足版本化 Token/字符预算；
- V1-V3 全量回归保持通过。

数据集、配置和报告必须版本化。通过结论不能只看答案更长；必须证明复杂任务的证据覆盖或引用质量有可重复提升，并且预算和失败率达到上述阈值。如果一次固定编排达到相同质量，应保留更简单路径，不扩大 Plan-and-Execute。

2026-08-17 固定离线与 DeepSeek 代表性运行结果见 [V4 Slice 1 评估报告](../../evals/reports/2026-08-17-v4-document-comparison-slice1.md)：离线候选范围化多步检索为 12/12，单轮 Top-K 5 为 0/12，对照子集双方均为 8/8；8 个代表案例各重复 3 次的真实模型候选多步为 9/9、单轮为 0/9，但候选 Token 为 2.64 倍、平均延迟为 3.25 倍。真实 PostgreSQL/pgvector、DashScope Embedding、持久化、SSE、重启和页面指标仍未执行且未计入通过结论。
