# ContextPilot 评估计划

> 状态：V1 功能型基线、V2 可控行动助手与 V3 知识库维护助手均已完成。V3 固定评估集、可重复 Maven Profile、首份基线报告、真实接口链路和页面目检已于 2026-08-15 全部通过。

## 目标

计划使用固定、可公开提交的问题集验证检索、引用和回答质量，避免只凭单次演示判断效果。该基线目前延期，在对外发布前补齐；不接入外部评估平台。

## 评估资产

- `evals/fixtures/documents/`：可公开的固定测试文档。
- `evals/datasets/`：问题、参考答案、期望引用和标签。
- `evals/configs/`：模型、切分、topK、阈值和提示词版本。
- `evals/reports/`：可选的脱敏基线报告。

## 最小用例类型

- 文档中存在直接答案的问题。
- 需要组合多个分段的问题。
- 文档没有答案、应明确拒答的问题。
- 身份介绍、问候、能力说明、感谢和告别应命中固定回复，附加知识问题或指令后不应绕过检索与拒答。
- 未选择知识库或缺少必要上下文、应返回澄清提示的问题。
- 容易命中相似但错误分段的问题。
- 带页码 PDF 的引用定位问题。
- 模型或 embedding 调用失败时的错误处理。
- SSE 中断后消息、模型调用状态和 trace ID 是否可关联。

## 指标

- 检索命中率：期望分段是否进入 topK。
- 引用正确率：引用是否支持对应回答。
- 回答忠实度：回答是否受检索内容支持。
- 拒答正确性：无依据时是否避免编造。
- 延迟和 Token：记录端到端耗时、首字时间和 Token 用量。
- 稳定性：固定配置多次运行的失败率和结果波动。
- 正向反馈：统计“有用”标记数量及其占已完成回答的比例，并可按知识库、trace ID 和时间段关联分析；未标记不直接视为负面或错误样本。

任何提示词、切分策略、检索参数、默认模型或引用格式变化，都应更新配置并重新生成基线。真实用户文档、密钥和未脱敏请求不得进入评估资产。

## V2 能力与操作评估

固定能力路由和 `CREATE_KNOWLEDGE_BASE` 操作已获准实现，至少覆盖：

- 能力路由准确率，以及无法唯一匹配时的澄清正确率。
- 普通知识问题、复合指令和相似措辞不会误触发业务操作。
- 未确认、已拒绝或已过期提案不会产生副作用。
- 强类型参数校验能拒绝空名称、超长名称和客户端篡改的动作类型或参数。
- 重复及并发确认只执行一次，状态迁移和 trace ID 审计完整。
- 操作失败只暴露安全摘要，历史会话能恢复提案及最终状态。

### 已建立资产与运行方式

- 固定数据集：`evals/datasets/v2-routing-action-safety-v1.json`。
- 固定配置与通过阈值：`evals/configs/v2-routing-action-safety-v1.json`。
- 可重复测试：后端 Maven `v2-evaluation` Profile，仅运行 `*EvaluationTests`；真实状态机案例使用 Testcontainers PostgreSQL/pgvector，缺少 Docker 时评估 Profile 必须失败，不能以跳过结果生成基线。
- 首份报告：`evals/reports/2026-08-14-v2-routing-action-safety-baseline.md`。

Windows 本地运行命令见 `evals/README.md`。路由规则、能力版本、动作参数、状态迁移或安全边界变化时，必须提升数据集或配置版本并重新生成报告。

V2 整体变更审阅、全量回归与前端构建结果见 [V2 版本验收报告](v2-acceptance-report.md)。

## V3 健康检查与维护评估（已完成）

V3 评估范围与完成标准见 [V3 知识库健康检查与维护助手详细设计](../architecture/v3-knowledge-base-maintenance-design.md)。实施过程中建立独立版本的数据集、配置、Maven Profile 和脱敏基线报告，至少覆盖：

- 健康检查确定性意图的准确率、误触发率和复合请求澄清；
- 空知识库、健康、处理中、失败、profile 未知、profile 过期和实际向量缺失；
- 向量查询不可用时 `PARTIAL` 完整性说明，不得错误判定完全健康或向量缺失；
- 知识库隔离、逻辑删除、明细上限和 `TRUNCATED` 语义；
- 历史报告按原 `dataAsOf` 恢复，不重新计算或静默变化；
- 重名文档通过报告明细 ID 精确选择，不以文件名猜测目标；
- 提案生成和确认两个时间点的实时复核，陈旧报告不产生错误副作用；
- 重试与重建动作的拒绝、过期、重复确认、并发确认和安全失败摘要；
- 事务提交后派发、队列拒绝保留 `PENDING`、恢复扫描和原子处理抢占；
- V1 RAG、引用、拒答、历史、反馈和 V2 创建知识库动作保持回归通过。

V3 固定评估必须使用真实 PostgreSQL/pgvector 容器验证健康报告、向量存在性和动作状态机。缺少 Docker 或真实生命周期案例被跳过时，评估 Profile 必须失败，不得据此生成通过报告。

V3 切片 1 至切片 7 已分别覆盖健康规则、不可变报告、聊天与 SSE、强类型动作核心、失败文档重试、索引重建及可靠派发。切片 8 已新增 `v3-health-maintenance-v1` 固定数据集与配置、`v3-evaluation` Maven Profile 和脱敏基线报告。2026-08-15 的专项运行共 118 项测试，0 失败、0 错误、0 跳过；16 条路由、12 条健康分类/完整性/资格案例和 9 类真实生命周期覆盖均达到阈值。真实接口验收覆盖固定 SSE 顺序、报告查询、可信明细生成提案、独立查询/拒绝和会话历史恢复；用户随后完成真实页面目检，确认报告卡片、动作卡片、刷新恢复与窄视口布局通过。详见 [V3 版本验收报告](v3-acceptance-report.md) 与 `evals/reports/2026-08-15-v3-health-maintenance-baseline.md`。
