# 阅读位置与回顾入口修复（2026-10-23）

用户反馈：回顾前必须手动点“已读到这里”，且回顾不可用。当前已确认的是入口阻碍和代码中的输出约束缺口；用户这次失败的具体错误/任务编号尚未提供，不能将历史 OUTPUT_INVALID 的原因推断为超长。

## 本轮修复

- 阅读位置仍独立自动保存。滚动时按待保存/已保存的位置判断是否写入，避免初始选中段落导致首段漏存；定位恢复时选中实际目标段落。
- 打开助手先采集并保存当前阅读位置。首次回顾直接使用已保存位置作为候选范围，在原有任务确认中明确确认连续前缀、当前整段和跳过内容，不再要求回正文另点标记。
- 已存在的 AI 边界保持不变；需要扩大时在助手勾选更新至保存位置。目录跳转、引用浏览和滚动本身不扩大 AI 范围。范围写入失败、冲突或助手关闭时不创建后续任务。
- Prompt 升级 reading-evidence-v4，明确已有的回顾 1200 / 查证 600 Unicode 字符总上限、最多 100 条事实及引用约束，不放宽验证、不截断答案、不自动重试。
- 回顾 JSON 同样拒绝重复字段及尾随内容。校验失败保留 OUTPUT_INVALID 公共码；日志只记录 workId 和 JSON_SCHEMA / FACT_TEXT_LIMIT / EVIDENCE_IDS 等固定类别，不记录原文、问题或模型输出。页面展示中文提示及任务编号。
