# 阅读人物查证拒答修复验证

2026-10-22。PR #38 已合并，本轮基于 develop/724c143 修复 [v5 DEBUG 的 debug-008 拒答缺陷](reading-live-v5-results.md)。新实现 acceptance-v6、Prompt reading-evidence-v2；仅完成离线修复与工程验证，真实模型重测及语义验收未完成。

## 问题与改动

旧协议仅返回 facts/partial，服务把非空 facts 判为完成。debug-008 问“明天的实际风力是多少”，原文只包含未署名纸条要求把明天风力写成九级。模型准确引用纸条但未正确拒答，说明有依据的相关事实仍可能答非所问。

新提示词先要求判断原文是否能回答当前问题，再提取直接回答的事实，明确区分说法、要求、计划、假设、预测和实际发生的事。对“文本要求什么”仍允许根据要求作答，对“实际发生什么”则不能用要求代替事实。没有为风力、九级、纸条或具体人物添加生产关键词规则。

人物查证在**原有同一次生成**中返回 answerability 与 facts；服务端按以下一致性规则转换到既有公开结果。它不是额外分类器或二次审查调用，不增加费用或调用上限。

| 模型响应 | 验证条件 | 对外结果 |
| --- | --- | --- |
| FULL | 非空 facts、既有引用与长度校验通过 | COMPLETED，partial=false |
| PARTIAL | 非空 facts、既有校验通过；提示词限定只输出可回答部分 | PARTIAL，partial=true |
| INSUFFICIENT_EVIDENCE | facts 必须为空 | INSUFFICIENT_EVIDENCE，facts=[] |
| 缺失、未知、重复字段、数字枚举、额外尾随 JSON 或判断/事实矛盾 | 无效协议 | FAILED / OUTPUT_INVALID，不发布结果 |

回顾仍采用原 facts/partial 模型响应；规划查询协议不变。仅 Prompt 版本升级。公共 Result、历史数据、笔记提案和确认、API 与数据库结构不变；没有新增依赖。新模型响应不能决定范围、调用预算、身份或执行工具。

## 验证与边界

- 直接读取已提交的 v5 debug-008 原始观测，确认旧的无可回答性字段响应无法通过新版人物协议；原观测及全部历史锁保持原字节。
- 合成响应覆盖完整、部分、证据不足、缺字段/未知枚举、数字枚举、矛盾空/非空事实、重复字段、尾随 JSON、伪造引用、无引用与超长事实。
- PostgreSQL 任务集成验证正确拒答、完整/部分结果、矛盾响应失败、不发布无效结果、实际 usage 保留、重复 clientRequestId 不增加调用；每个直接查证仍只有一次 query embedding 和一次回答。
- 原阅读导入/范围/取消/迟到结果、预算预警/停止、笔记不可变提案与原子确认、本地 HTTP 协议继续回归。测试使用 Testcontainers 与本地/离线替身，不调用真实供应商。

以 JDK 21 执行 backend 下的 `./mvnw.cmd "-Dtest=Reading*Tests" test`：100 项，0 失败/错误，2 项条件跳过；根目录 `node --test evals/tools/reading*.test.mjs`：24 项通过。最终提示词示例澄清与 usage 断言补充后，另跑 ReadingTaskPolicyTests/ReadingTaskPersistenceTests：29 项，0 失败/错误，1 项条件跳过。acceptance-v6 资产与源码哈希校验通过。原有两个浏览器夹具条件跳过不构成浏览器体验验证；前端和公共响应格式未变，不重跑无关构建。

**一致性校验不能证明 answerability 判断正确。** 若真实模型把同样的相关背景标为 FULL，现有结构/引用校验仍可能放行；本轮不能声称 debug-008 的真实语义问题已验证解决。合成正反例只验证应用处理，不算真实模型成绩。冻结 TEST 的问题、参考事实、评分和重复次数不变，没有用 TEST 调 Prompt。

## 冻结与后续

当前 CLI 与后端新批次仅接受 acceptance-v6；v1–v5 配置/锁、固定 v1 数据集及 v5 原始证据保留。v6 新锁也覆盖回放用的 v5 DEBUG 观测；这是已失败调试样本，不是 TEST 答案注入。

没有新建可执行 plan/approval，没有启动原隔离评测服务，没有清空停止原因或消耗，也没有新增付费调用。既有授权额度仍有效作为历史总额，停止批次不可自动重跑。后续需准备新实现对应的 DEBUG 重测清单，明确扣除旧消费后的剩余金额及有效时间；用户主动发起重测后执行。真实 DEBUG 复核前不放行 TEST，不用模型协议回归冒充语义或读者体验验收。
