## 有界修复与验证

仅对授权 `check()` 的 `ReadingException` 排除自动标记回滚，使调用方能在范围事务内返回停止状态。数据库异常仍回滚；创建任务时拒绝异常仍传播到外层事务并阻止写入。没有放宽模型输出校验、预算门禁或停止规则。

原试读集成测试直接构造授权对象，漏掉了 Spring 事务代理行为。本次改为使用真实事务拦截器，并覆盖本地 HTTP 模型失败后：索引状态与费用估算可查询、停止原因保留、创建任务被拒绝、重建授权对象仍不可恢复、调用数不增长。

修复前新回归稳定复现 HTTP 503 和 `UnexpectedRollbackException`（期望 HTTP 200）。修复后授权、试读、持久化、供应商协议、输出策略及完整性六组测试共 81 项，80 通过、1 项沿用既有跳过，零失败。随后按用户新要求补入 DIRECT_LIVE 开关与本地 HTTP 全流程回归，最终六组共 83 项，82 通过，1 项 `reading.ui` 浏览器夹具因未启用而跳过。前端 typecheck/build 通过（已有 bundle 体积提醒）。新增测试首次编译有一处泛型断言类型错误，修正后通过上述检查。新实现冻结 acceptance-v11，Prompt 保持 reading-evidence-v3；v1–v10 配置和锁保留，不安装新批准文件。旧试读进程已按用户要求停止，没有部署或自动真实调用。
