## 目标用户与价值

面向阅读长篇小说、会中断阅读、容易遗忘前情与人物的读者，帮助其记住故事、查证人物并快速接着读。求职目标是以完整业务展示 AI/Agent 应用开发能力，包含业务建模、受控检索、证据引用、有界任务、人机确认及评估。

首个场景是读者隔了一段时间返回：打开书架，恢复上次位置，确认已读范围，查看前情回顾，查证人物，跳转原文，选择是否保存回顾笔记，然后继续阅读。

## 首版产品范围

| 用户需求 | 规划范围 | 核心约束 |
| --- | --- | --- |
| 导入并阅读自己的小说 | UTF-8 TXT/Markdown、目录预览、书架、章节阅读和基础阅读设置 | 用户有权使用；正文版本不可变；AI 索引失败不阻断阅读 |
| 中断后继续阅读 | 自动保存续读位置、书签 | 续读位置与已读边界分开，回看引用不改变原续读位置 |
| 控制 AI 可以知道什么 | 用户明确设置段落级连续已读范围 | 跳读不自动推进边界，同章未读段落不可使用 |
| 迅速恢复前情 | 默认最近三个已读章节的回顾，当前章仅含已确认段落 | 展示覆盖范围，超预算不冒称完整，不默认总结全部已读长篇 |
| 查证人物并核实事实 | 已读范围内的人物身份、行为、关系查证及原文跳转 | 有依据才回答；身份揭密、因果和后续剧情不可从范围外补入 |
| 留下阅读记录 | 手写笔记、摘录、经确认保存的 AI 回顾 | AI 保存需持久提案、独立确认、原子幂等；不写入回答偏好 |
| 单用户使用 | 本机或可信网络内的 Web 应用 | LOCAL_OWNER 是归属而非认证，不提供公开多用户服务 |

上述为新路线的产品范围。用户已批准 `reading-contract-v1-draft1` 的[业务/页面合同](../architecture/novel-reading-design.md)、[数据](../data/novel-reading-data-model.md)、[API](../api/novel-reading-api.md)、[评估方法](../evaluation/novel-reading-evaluation.md)。基础阅读、范围、阅读任务和确认保存笔记的离线链路已实现；用户再次要求下一能力后，本轮准备固定评测资产、离线体验证据和展示材料，不新增产品范围。真实 AI 适配、语义与真实读者体验验收尚未完成；具体预算与门槛只在[新路线](../development/novel-reading-roadmap.md)维护。每轮推进一个大功能点后提醒用户提交 PR，付费实验单独授权。

合同具体化：首次导入不自动花费 embedding 费用；基础阅读独立可用，回顾直接读取范围内正文，人物查证使用用户主动建立的已读索引。笔记/历史/引用在边界回退后统一隐藏较后内容。首版不复用跨任务生成答案、不构建全书人物表，复杂查证由用户主动选择。既有工作区保留直接入口，新阅读页面使用独立路由，技术标识与当前展示名称保持不变。

## 正确性与体验要求

- 不依赖 AI 也能完成阅读、续读、书签与手写笔记。
- 检索、摘要、人物资料、缓存、历史、笔记可见性和引用遵循一致的书籍/版本/已读范围；进度回退不能泄露后期结果。
- 原文事实、用户笔记与模型生成内容有清晰来源；引用必须支持其绑定的事实，合法编号不能替代语义验证。
- 防剧透是待验证的核心目标，不能仅靠提示词或承诺绝对保证；模型先验知识也纳入测试。
- 失败、证据不足和覆盖不足明确区分，用户始终能返回阅读；生成结果通过校验后再发布。

## 范围外与后续候选

首版不包含 EPUB/PDF 小说导入、OCR、抓站、版权书城、付费分发、社区、创作工具、角色陪聊、音频、原生移动端、离线阅读、账号或多设备同步。EPUB、人物关系图、全量已读剧情梳理和分层摘要可后续讨论，不自动排期。

不默认扩建混合检索、Rerank、通用 MCP、多 Agent 或工作流引擎。现有专用 MCP 仅用于固定 Spring AI 项目资料，不能扩展为小说抓取授权。
