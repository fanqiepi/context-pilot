# 公开模型结果观察

2026-10-19，固定四类公开合成样本各执行两次。原始输入、输出、usage 与执行时间见 `live-results.json`；文件哈希与模型版本见 `manifest.json`。这是编码助手逐条对照输入证据的观察，不是独立人工最终验收。

| 样本 | 次数 | 观察 |
| --- | --- | --- |
| SUPPORTED | 1 | FIFO 断言得到支持；模型额外提出并发和多工作进程范围缺口，超出给定目标，导致总体 NEEDS_MORE_EVIDENCE。记录为过度审查。 |
| SUPPORTED | 2 | FIFO 断言得到支持，无缺口，NO_ISSUES_FOUND。 |
| PARTIAL | 1 | 拆为 FIFO 有支持、三次重试无支持；总体 ISSUES_FOUND，符合冻结的可接受拆分口径。 |
| PARTIAL | 2 | 合并断言为 PARTIAL，识别重试次数无依据；额外要求区分 demo/生产工作进程，存在范围扩张。 |
| UNSUPPORTED | 1、2 | 正确指出没有吞吐测试数据，不能推出每秒一万项；未误判为证据矛盾。 |
| CONTRADICTED | 1、2 | 正确指出“不支持优先级”与答案相反；建议中又扩展到其他工作进程，属于非阻断质量问题。 |

八次都通过结构与引用 ID 校验；这一结果不能证明事实准确率、完整覆盖率或无提示注入风险。现有样本未发现主断言漏判，但单句合成样本规模不足以外推。工程测试、调用成功与语义判断分别记录，不把审查器自己的结论当成独立验收。

后续集中优化：减少目标之外的假设性缺口；在独立长答案集上评估多断言覆盖、误报与漏报；保持原始失败和过度审查观察，不通过改写本测试集宣称提升。

页面真实流程补充：第二轮审查将 FIFO 的“先进先出”释义判为 PARTIAL，虽然核心 FIFO 断言被识别为有支持。这是过于字面的证据判定，不能把总体判定直接当作质量真值。该轮也正确识别了重试次数无资料支持。用户编辑建议后第三轮研究完成；页面产物与失败记录见 page-flow.json。

## 最终传输配置复验

最终 JDK HTTP 配置下再次运行四类各两次，八次均通过执行/结构门禁，原始结果见 final-live-results.json。SUPPORTED 第一次符合预期，第二次因假设“所有工作进程”而降为 PARTIAL，属于过度扩大断言范围。PARTIAL 两次均正确拆为 FIFO 有支持、重试上限无支持。UNSUPPORTED 第一次误判为 CONTRADICTED：没有性能测量并不能反证具体吞吐数字，这是语义分类错误；第二次正确判为 UNSUPPORTED。CONTRADICTED 两次均与证据一致。

累计两批 16 次调用的执行成功不等于 16 次语义正确。保留首批与最终批全部输出，不通过只选成功批次宣称质量达标。该原型可展示证据和问题供用户核对，不能作为自动事实裁决；独立质量验收仍未完成。
